0 · About this file

OAO design prototype

A standalone reference for iterating on the OAO console design before touching the application. Light-first, squared geometry (0–4 px radii), thin borders, restrained shadows, translucent glass only on floating chrome, no gradients anywhere. The palette stays anchored on the approved seed #6ebc91, with darker greens (700/800) carrying text and actions for contrast.

⚠︎
Prototype only. Nothing here has been applied to the OAO application. Use this page to review and iterate; port approved decisions to the app afterwards.

Rules
  • Borders separate; shadows elevate. A surface gets a shadow only if it floats above the page (menu, dialog, toast) or frames an app preview.
  • Glass (translucency + blur) is reserved for sticky chrome — top bars and floating headers. Never on content cards.
  • Seed green 500 is a signal color (focus rings, live dots, charts). Text and buttons use green 700 on light, green 400 on dark.
  • Avoid: gradients (banned), radii above 4 px except status-chip pills, more than one accent hue per view.
2 · Components

Buttons

One primary action per view. Everything else is secondary (bordered), ghost (toolbars, table rows), or danger (destructive, always behind a confirm dialog).

Variants

Link as button

Sizes

States (hover / focus rendered statically for review)

Rules
  • Use primary for the single next safe action (Create agent, Approve). Two primaries on screen means the hierarchy is broken.
  • Ghost buttons live inside toolbars, table rows and card headers where a border would add noise.
  • Loading buttons keep their width, show a spinner, and set aria-disabled — don't swap them for a skeleton.
  • Avoid: icon-only buttons without aria-label, pill-shaped buttons, uppercase button labels.

Rules
  • Always visible labels — placeholders are examples, never labels. Mark required fields, not optional ones.
  • Validate on submit (plus on blur for expensive checks like slug availability). Errors are inline text tied via aria-describedby, not toast-only.
  • Switches apply immediately (settings); checkboxes wait for the form submit. Don't mix the two behaviors in one panel.
  • Avoid: three-plus column forms, center-aligned labels, disabling the submit button as the only validation feedback.
4 · Components

Dropdowns & menus

Action menus float on --shadow-3 with a 4 px radius. Fully keyboard-operable: ↵ / ↓ opens, arrows cycle, Esc closes and returns focus.

Interactive action menu

← try it with the keyboard
Rules
  • Menus hold actions; use a native <select> for choosing a value in a form.
  • Destructive items sit last, after a separator, in danger red, and always end with “…” because a confirm dialog follows.
  • Disabled items stay visible with aria-disabled so users learn what exists — never silently remove them.
  • Avoid: nested submenus (restructure instead), menus longer than ~9 items, mixing navigation links and actions in one menu.
5 · Components

Dialogs

Native <dialog> with a scrim, 440 px default width, actions right-aligned in a footer. Focus is trapped by the platform; Esc cancels.

Archive “Shipment investigator”?

Rules
  • Dialogs are for short, blocking decisions or one-to-three-field forms. Longer flows deserve a page.
  • Confirm titles name the object (“Archive ‘Shipment investigator’?”) and the confirm button repeats the verb — never “OK”.
  • The cancel action must be a real button; don't rely on Esc alone.
  • Avoid: nested dialogs, dialogs that open on page load, destructive primary buttons in green.

The one sanctioned pill shape. Every status pairs color with a label — color alone never carries meaning.

Rules
  • Green = healthy/approved, amber = waiting on a human, red = failed, blue = system-neutral in-flight, gray = inert.
  • The animated live dot is only for genuinely streaming work; it pauses under prefers-reduced-motion.
  • Progress bars turn amber above 85% of a quota — don't invent intermediate colors.
  • Avoid: chips as buttons, more than one chip per table row, sentence-length chip labels.

Rules
  • Transcript role labels are mono and color-coded (blue user, green assistant, amber tool, gray system) with the same colors reused in the waterfall.

Rules
  • Secrets show a masked prefix + last four; the full value appears exactly once, at creation, inside the dialog.
  • Flag stale credentials (unused 90 days) with a warning chip — nudge, don't auto-revoke.
  • Revoke is an inline danger button because it is common and reversible by re-issuing; deletion of agents is not, so it hides behind a menu + dialog.
  • Avoid: eye-toggle reveals of stored secrets, copying keys to clipboard without a confirming toast.
12 · Feedback

Toasts & alerts

Toasts confirm what just happened (transient, bottom-right, auto-dismiss ~5s). Alerts describe a persistent condition and stay put until resolved.

Trigger toasts

Persistent alerts

ℹ︎
Scheduled maintenance The EU runtime restarts tonight 02:00–02:10 CET. Running sessions resume automatically.
✓
All systems operational 182 sessions completed in the last 24 h with 0.4% errors.
⚠︎
Key expiring ci-deploy rotates in 6 days. Update your CI secrets before then.
✕
Provider degraded openrouter/gpt-5 is returning elevated 529s. Affected agents fall back to claude-sonnet.
Rules
  • Toast = past tense, one line, optional single action (Undo). If it needs two actions or a paragraph, it's a dialog or alert.
  • Errors that block the user's current task render inline where the task is — never toast-only.
  • The toast region is aria-live="polite"; stack at most three, oldest drops first.
  • Avoid: toasts for validation errors, success toasts for pure navigation, center-screen toasts.
13 · Feedback

Empty, loading & error states

Every list surface ships all three. Skeletons pulse opacity (no shimmer gradients) and match the real layout so nothing jumps on load.

◇

No agents yet

Agents are durable runtimes with versioned prompts and tool access.

Loading (skeleton)

✕

Couldn't load sessions

The API returned 503. Your agents are unaffected; this is a console issue.

Rules
  • Empty states teach: one sentence on what the object is, then the primary creation action. Dashed border marks “nothing here yet”.
  • Error states say what failed, what is still safe, and offer Retry. Never a bare “Something went wrong”.
  • Show skeletons only after ~300 ms so fast loads don't flash; they're aria-hidden with loading announced on the region.
  • Avoid: illustration-heavy empty states, spinners for full-page loads (use skeletons), blaming the user in error copy.
